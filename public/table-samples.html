Three ways to draw the CaPSA table

Same rows, same colours, same eight-pixel rhythm you already have — the difference is how much each row is asked to carry. All three use the palette in admin.css, so whichever you pick drops into the page without introducing a new colour.

A.Refined — what you have, tightened

The smallest change. Header becomes a shaded band so the column names stop competing with the data; actions move right and become icons with the two named ones kept as text; sections move under the role badge they belong to. Row height drops from 60px to 52px.

B.Two-line — room for what a row carries

For rows that hold several things at once. Each cell gets a tiny label above it, so a person with three roles and four sections stays readable instead of wrapping into mush. Costs about 20px of height per row; worth it while you have a handful of CaPSAs, wasteful at forty.

C.Compact — built for scrolling

One line per person, 33px rows, header stays put while you scroll. Status becomes a coloured dot beside the name rather than its own column, which buys back the width. This is the one to pick if the list is ever going to hold every faculty member rather than a few CaPSAs.

1 · Today — breaks quietly

Two names joined then cut with an ellipsis, so the second one is half a word and the count is the only honest part. At nine skills it reads exactly the same as at three.

2 · Chips + counter

Each name is its own object and truncates on its own, so nothing turns into half a word. Width still grows with the names; the +7 has to open something.

3 · Group counts — bounded

There are only five groups in SkillCatalog, ever. Nine skills and ninety render the same width. You lose the exact names — the search box and the detail panel already have those.

4 · Strongest + count

Narrowest of all, and honest about being a summary. But "strongest" is a judgement nothing in the data supports — it would just be whichever row was saved first.
